Data Engineering · Real-Time · ML in production

Delay Prediction for Madrid Commuter Rail

Renfe reports delays only once they are happening and publishes no history. I built the 24/7 capture system that creates that history and the public web app that turns it into an arrival prediction. Master's thesis (UCM), 1st Prize in the scholarship competition, team of five: my part was the infrastructure, data capture, the app and team coordination.

Python GTFS-Realtime AEMET API Parquet systemd · Linux FastAPI Databricks · MLflow LightGBM rclone
  • 12 million records in 92 days, captured every minute, with 99.7% availability
  • Real-time to timetable match rate raised from 0% to 99.9% by recovering versions the operator does not keep
  • Immutable raw layer, Parquet analytics layer and daily cloud backup
  • Content monitoring: alert within 10 minutes if a source stops making sense
  • LightGBM model: error down from 283.2 to 147.7 s vs historical baseline (−48%)
  • On real trains: 6.18 min error vs 9.08 for the official timetable
